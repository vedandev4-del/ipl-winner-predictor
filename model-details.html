How the IPL Winner Predictor Model Works

This project is a machine-learning application that estimates the probability of a team winning a second-innings IPL match based on the match information entered by the user.

1. Match information entered by the user

  • Batting team
  • Bowling team
  • Host city
  • Target score
  • Current score
  • Overs completed
  • Wickets lost

The available teams and cities are defined in the application's Python code. The model's results depend on these inputs and the training data used to build the saved pipeline.

2. Features calculated by the application

Runs remaining

runs_left = target - score

Balls remaining

balls_left = 120 - (overs × 6)

Wickets remaining

wickets_remaining = 10 - wickets_lost

Current run rate (CRR)

CRR = score / overs_completed

Required run rate (RRR)

RRR = (runs_remaining × 6) / balls_remaining

These features describe the chase situation. The application passes them, along with the teams, city, and target, to its prediction pipeline.

3. The prediction pipeline

The application loads a saved pipeline from a file named pipe.pkl. When the user clicks Predict Probability, it creates a pandas DataFrame containing the calculated features and calls the pipeline's predict_proba() method.

The code interprets the first returned probability as the bowling team's outcome and the second as the batting team's outcome. This interpretation depends on the class ordering used when the model was trained.

The specific estimator, training dataset, and measured predictive performance cannot be confirmed from the application code alone.

4. Understanding the displayed probabilities

The application displays rounded percentages for the batting and bowling teams. These are model-generated estimates, not guaranteed outcomes. The reliability of the probabilities depends on the underlying model and its validation.

5. Important limitations

  • The output depends on the accuracy of the entered match information.
  • The model may not account for every real-world match condition.
  • Predictions can be wrong, even when a team has a high estimated probability.
  • No accuracy score is claimed here because verified evaluation results have not been provided.
